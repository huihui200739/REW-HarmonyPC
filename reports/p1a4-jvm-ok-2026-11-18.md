# T0 达成：JVM 在 HarmonyOS PC 应用内成功启动 · 2026-11-18

## 结果

```
stage: dlopen shim → ok
stage: dlopen libjvm.so → done
stage: JNI_CreateJavaVM rc=0
JNI_CreateJavaVM: OK
java.version=17.0.17-internal
java.vm.name=OpenJDK 64-Bit Server VM
java.home=/data/storage/el2/base/haps/entry/files/jre
os.arch=aarch64
FindClass(ArrayList)=OK
DONE
```

设备：HarmonyOS 模拟器（emulator 6.1.0.125，API 24，arm64，2in1），应用 com.example.rewharmony。

## 三个修复（缺一不可）

### 1. java.home：HotSpot OHOS 补丁的覆盖逻辑

补丁 0003 读 `ECLIPSE_EMBEDDED_JAVA_HOME`，未设置时从 libjvm.so 路径反推 → 得到 HAP bundle 根 →
`lib/modules` 不存在 → `Failed setting boot class path`。

修复：`setenv("ECLIPSE_EMBEDDED_JAVA_HOME", javaHome, 1)`。

### 2. libjava.so 缺 20 个 musl 没有的符号

```
jcos jsin jtan jacos jasin jatan jatan2 jcosh jsinh jtanh jexpm1 jlog jlog10 jlog1p jremainder jsqrt
__xpg_strerror_r __register_frame_info __deregister_frame_info __at_fini collector_func_load
```

根因：`libfdlibm` 没有链接进 `libjava.so`（`LIBS := $(BUILD_LIBFDLIBM_TARGET)` 在本环境取空），
另外 4 个是 glibc 专有符号。

临时方案（已生效）：`app/entry/src/main/cpp/jvm_shim.c` 编译为 `libjdkshim.so`，
数学函数转调平台 libm，glibc 专有符号给空实现。
**代价**：`StrictMath` 不再位精确（对测量软件影响可忽略，但要在文档里标注）。

### 3. 符号可见性：OHOS linker 不做全局符号解析

即使 `dlsym(RTLD_DEFAULT, "jcos")` 能命中，`libjava.so` 加载时仍报 `symbol not found`——
OHOS 的 linker 只在该库的 `DT_NEEDED` 闭包内解析符号。

修复：`patchelf --add-needed libjdkshim.so libjava.so`，把 shim 变成它的直接依赖。

```
NEEDED: libjdkshim.so / libjvm.so / libc.so
```

## 复现链

```bash
jvm/fetch-jdk.sh && jvm/apply-jdk-patches.sh && jvm/configure-jdk.sh
jvm/build-jvm.sh --jobs 6
jvm/build-runtime.sh
# 打包：entry/libs/arm64-v8a 放 9 个 JVM .so + libc++_shared + libjdkshim
#       entry/src/main/resources/rawfile/jre-runtime.zip 放 runtime（去 .so）
#       patchelf --add-needed libjdkshim.so libjava.so
# 构建：hvigorw assembleHap（工程须在纯英文路径）
```

## 这证明了什么 / 没证明什么

**证明**：OpenJDK 17 HotSpot 能在 OHOS 应用沙箱内完成初始化、读 modules、加载 java.base、执行字节码（FindClass 成功）。

**没证明**：AWT/Swing（java.desktop 不在 runtime 里）、Java Sound、JIT 性能（当前 -Xint）、REW 本体启动。
